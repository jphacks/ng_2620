# ADR-0011 入力は 180 秒・長辺 1920px まで。推論はプロキシ解像度、書き出しはフル解像度

- 状態：採択
- 日付：2026-10-24（2026-10-25 改訂：長さの上限を 30 秒から 180 秒に。[改訂](#改訂2026-10-25長さの上限を-180-秒に)）

## 文脈
- 処理時間は RTX 5060 Ti で約 0.72 秒/フレーム（2026-10-24 計測、`--hmr_stride 3`、3DPW 120 フレーム 2 本、`scripts/eval/e2e.py`）。30fps の 30 秒（900 フレーム）は約 11 分。
- パイプラインは縮小した解像度（`images/`、480x854 など）で追跡・メッシュ・遮蔽判定を行い、`avatar_app.py --hq <元動画>` で元解像度に合成できる（整数倍の拡大が GPU 経路の条件）。
- スマートフォン動画は HEVC・可変フレームレート・回転メタデータを含むことが多い。

## 決定
| 項目 | 値 |
|---|---|
| 長さ | **180 秒以下**（超過は取り込み時に拒否し、トリミングを案内。P1 で取り込み時の区間指定）。サーバーの `VVLOG_MAX_DURATION_SEC` で変えられ、アプリは `capabilities.limits.maxDurationSec` を読む |
| 解像度 | 長辺 **1920px 以下**（4K は拒否し、縮小を案内） |
| フレームレート | 30fps 以下に**固定フレームレートへ変換**（可変は `ingest` で CFR 化）。60fps は 30fps に間引く |
| 形式 | mp4 / mov（H.264 / HEVC）。音声は AAC として保持し、書き出しで再多重化 |
| 回転 | 回転メタデータを適用してから処理（縦動画を正しく扱う） |
| プロキシ（推論・プレビュー） | フル解像度を**整数分の 1** に縮小し、短辺が 480px に最も近いもの（1080x1920 → 1/2 = **540x960**。1/2.25 = 480x854 は整数倍でないので使わない）。決め方は `ingest` が一元管理。L4 での 2026-10-24 の実測（480x854）より画素数が約 26% 多く、処理時間は 1〜2 割増える見込み |
| 書き出し | フル解像度（`--hq`）。H.264 CRF 18、yuv420p、元の音声 |

## 影響
- 「整数分の 1」の制約は、GPU 合成経路（`avatar_app.py` の `--hq` 整数倍）に合わせたもの。`ingest` がプロキシ寸法とスケールを `meta.json` に書き、後段はそれだけを見る。
- デモ素材は 10 秒前後（約 4 分）を推奨。30 秒は「キューに入れて放置」の体験として見せる。

## 改訂（2026-10-25）：長さの上限を 180 秒に
- 実際の vlog は 30 秒を超えることが多く、2 分強の動画（iPhone、1280x720・30fps・132.1 秒・3963 フレーム、2 人）を RTX 4070 SUPER（12GB）で最後まで通せた。
  - 所要時間：解析 約 27 分（ingest 8 s・track 463 s・mesh 231 s・occlusion 946 s）、描画 約 11 分、書き出し（フル解像度・CRF 14）約 14 分。合計 約 52 分。
  - VRAM は足りた（HMR の段で最大 約 3.8GB）。
  - ディスク：サーバーの作業データが 約 21GB（うち遮蔽判定のキャッシュ `occ/_r3cache` だけで 13GB 超）。空き 11GB の C ドライブでは遮蔽判定の段で `No space left on device` になり、`VVLOG_DATA_ROOT` を空きのあるドライブに移して通した。
- 上限は 180 秒（3 分）にする。132 秒の実測から、180 秒ではおよそ 70 分・30GB 前後を見込む。**`VVLOG_DATA_ROOT` には 30GB 以上の空きを用意する**。
- 長さは処理時間とディスクにほぼ比例するので、機械に合わせて `VVLOG_MAX_DURATION_SEC` で下げてよい。
