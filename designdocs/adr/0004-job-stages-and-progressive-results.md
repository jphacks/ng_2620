# ADR-0004 ジョブは analyze / render / export の 3 種。ステージ単位で成果物を公開し SSE で通知する

- 状態：採択
- 日付：2026-10-24

## 文脈
- 現行パイプラインは 2 プロセス（`offline_app_lite.py`：検出・追跡・メッシュ、`avatar_app.py`：遮蔽判定・除去・描画・合成）で、10 秒動画に約 4 分かかる（RTX 5060 Ti）。
- 体験の要求：待ち時間中も結果が段階的に見えること、複数ジョブをキューで回せること（ユーザー回答「両方」）。
- 人物の選択と VRM の割当はユーザー操作なので、**VRM に依存しない処理**（追跡・メッシュ・遮蔽判定）と**依存する処理**（描画）を分ける必要がある。

## 決定
ジョブを 3 種に分け、ジョブ内のステージが終わるたびに成果物を公開する。

| ジョブ | ステージ | 入力 | 公開する成果物 | VRM 依存 |
|---|---|---|---|---|
| `analyze` | `ingest` → `track` → `mesh` → `occlusion` | ソース動画 | `ingest`：プロキシフレーム、メタ情報 / `track`：人物一覧・サムネイル・追跡マスク / `mesh`：メッシュのオーバーレイ動画 / `occlusion`：自動の隠れマスク・遮蔽物ユニット | なし |
| `render` | `removal` → `avatar` → `layers` | analyze の結果＋キャスト（ターゲットと VRM）＋仕上げパラメータ | クリーンプレート、人物ごとのアバター RGBA・深度順、プレビュー合成の動画 | あり |
| `export` | `composite` → `encode` | render の結果＋手修正＋書き出し設定 | MP4（H.264＋音声） | あり |

- **キャストの選択は `track` の完了後**にできる。`mesh` と `occlusion` が裏で続いている間に VRM を選べる（待ち時間を操作時間に変える）。
- `render` は `analyze` の完了を待つ。アプリは「キャスト確定」で `render` をキューに入れ、サーバーは依存が満たされた時点で開始する。
- 進捗は **SSE**（`GET /v1/jobs/{id}/events`）で配信する。イベントは `stage_started` / `progress` / `artifact_ready` / `stage_finished` / `job_finished` / `job_failed`（[contracts](../architecture/contracts.md#3-ジョブとイベント)）。
- サーバーのキューは GPU 1 枚につき 1 本の FIFO。アプリはキュー全体（自分のジョブと位置）を表示する。

## 却下した案
| 案 | 却下理由 |
|---|---|
| 1 ジョブで全部（現行 e2e と同じ） | VRM を最初に決めないと始められない。途中結果が見えない |
| ステージごとに別ジョブ（細かすぎる分割） | 依存管理がアプリ側に漏れる。ユーザーにとっての単位（解析・描画・書き出し）と合わない |
| ポーリング | 実装は簡単だが、段階的プレビューの即時性が落ちる。SSE が切れたときのフォールバックとしてだけ使う |

## 影響
- サーバーはパイプラインをステージ単位に呼び分ける必要がある（[pipeline-integration](../architecture/pipeline-integration.md)）。
- `render` だけをやり直せる（VRM の差し替え・仕上げパラメータの変更、P1）。
- `export` は `render` の成果物＋手修正で合成するので、手修正のたびに再推論はしない。
