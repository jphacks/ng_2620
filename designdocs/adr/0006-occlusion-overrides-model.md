# ADR-0006 前後関係の手修正は「遮蔽物ユニット × 区間 × 前/後ろ」のオーバーライドで表し、アプリが正本を持つ

- 状態：採択
- 日付：2026-10-24

## 文脈
- fusion v2 は、人物の手前にありうる物体の候補（SAM3 の点プロンプト候補をフレーム間でつないだもの）ごとに「人物の前か後ろか」を決め、人物ごとの隠れマスク（hide）を出す。
- 自動判定が誤る典型：机・楽器・手に持った物が後ろ扱いになりアバターが上に描かれる／背景の物が前扱いになりアバターが欠ける。
- ユーザーが直す単位は「物体」と「時間の区間」。画素を毎フレーム塗らせるのは動画では非現実的。
- 現行の候補のつながりは短い（キーフレーム方式で最大 10 フレーム程度、c2f では平均 3〜6 フレーム）。

## 決定
1. サーバーは `analyze/occlusion` で**遮蔽物ユニット**を公開する：
   - フレームごとのラベル画像（`units/{frame}.png`、16bit、0 = なし、1..N = `unitId`）。ユニットは**区間方向に連結済み**（キーフレームをまたいで IoU でつなぐ。[pipeline-integration](../architecture/pipeline-integration.md)）。
   - `units.json`：ユニットごとに、出現フレーム範囲と、人物ごとの自動判定（`front` / `behind`）と確信度。
2. アプリの手修正は次のレコードの列（`overrides.json`、プロジェクト内に保存）：
   ```json
   { "id": "ovr_01", "personId": 1, "unitId": 12, "range": [40, 95], "mode": "front" }
   ```
   `mode` は `front`（人物の前＝アバターを隠す）/ `behind`（後ろ＝隠さない）。`auto` に戻す＝レコードの削除。
   P1 のブラシは `{ "kind": "brush", "personId", "frame", "maskPng", "mode" }` を同じ列に足す（後勝ち）。
3. **有効な隠れマスク**は、自動の隠れマスクに、ユニットのマスク（そのフレーム・その範囲）を `front` なら OR、`behind` なら AND NOT で適用した結果（[contracts §5](../architecture/contracts.md#5-合成規則composite-rule)）。
4. 手修正の**正本はアプリ（プロジェクトファイル）**。サーバーは状態を持たず、`export` のたびにオーバーライドを受け取る。

## 却下した案
| 案 | 却下理由 |
|---|---|
| 修正をサーバーに保存し再判定させる（fusion の decide を再実行） | 往復が遅い。fusion の判定は CPU で数十秒。編集の即時性が出ない |
| ブラシのみ | 動画の全フレームを塗る負担が大きい。デモで価値が伝わらない |
| 修正のたびに SAM3 でマスクを作り直す | GPU 往復。P1 の「取りこぼし物体の追加」でだけ使う |

## 影響
- サーバー：ユニットの連結（区間方向）と `units/` / `units.json` の書き出しを `occlusion` ステージに追加する（レーン C）。
- アプリ：ユニットのラベル画像を WebGL テクスチャとして読み、ユニット×人物ごとの前/後ろテーブル（小さなテクスチャか uniform 配列）で合成する（レーン B）。
- 区間が切れているユニットは、クリック時に「同じ物体らしいユニット」をまとめて選ぶ補助（IoU 連結の候補表示）を P1 で足せる。
