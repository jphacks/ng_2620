# ADR-0007 プロジェクトはローカルのフォルダ形式 *.vvlog/（JSON＋キャッシュ）、スキーマ版付き

- 状態：採択
- 日付：2026-10-24

## 文脈
- 手修正の正本はアプリ側（[ADR-0006](0006-occlusion-overrides-model.md)）。アプリを閉じても、サーバーを替えても作業が残る必要がある。
- プレビューのレイヤー（数百〜数千ファイル）をキャッシュしたい。サーバーが無くても同梱プロジェクトを開きたい（[ADR-0009](0009-demo-resilience.md)）。
- 将来はチームでの共有・クラウド保存もありうる（スコープ外）。

## 決定
プロジェクトは**フォルダ** `<名前>.vvlog/`：

```
MyClip.vvlog/
  project.json        正本（スキーマ版 schemaVersion、ソース動画の参照、キャスト、手修正、ジョブ履歴、サーバー側 ID）
  overrides.json      手修正（project.json から分ける：頻繁に書くため）
  source/             ソース動画のコピー（任意。既定は元ファイルへの参照のみ）
  cache/<jobId>/...   サーバーから取り寄せた成果物（プロキシフレーム、マスク、レイヤー）。消しても再取得できる
  exports/            書き出した動画
```

- `project.json` は JSON Schema（`packages/contracts/project.schema.json`）で検証し、`schemaVersion` を必ず持つ。読み込み時にマイグレーション関数を通す。
- 書き込みは**一時ファイル → rename** で原子的に行う（保存中のクラッシュで壊さない）。自動保存（変更から 1 秒後）。
- サーバー側の `projectId` と各ジョブの `jobId` を記録し、再接続時にジョブ状態と成果物を復元する。

## 却下した案
| 案 | 却下理由 |
|---|---|
| SQLite 1 ファイル | キャッシュの大量の画像を入れると重い。中身を目で見て直せない（ハッカソン中のデバッグ性） |
| zip 1 ファイル | 書き込みのたびに再圧縮が要る。キャッシュの部分更新に向かない |
| サーバーに保存 | オフライン・サーバー切替に耐えない |

## 影響
- macOS では将来 `.vvlog` をパッケージ（バンドル）として 1 ファイルに見せられる（Info.plist の UTI 宣言、P2）。
- `cache/` は再生成できるので、共有するときは除外してよい。

## 補足（ADR-0015、#52）：Tauri 廃止後の互換とバージョン方針
- **形式は変えない**。Tauri 版が作ったプロジェクトフォルダは、ブラウザ版（制限モード）でもローカルサーバー版（フルモード）でもそのまま開ける。テスト：`fixtures/synth/synth.vvlog` を両方の経路で開く（`infrastructure/project/compat.test.ts`、実サーバー越しは `local/localApi.integration.test.ts`）。
- **絶対パスの参照は書き換えない**。`source.path`（元の動画）と `jobs.exports[].file`（書き出し先）は、別の PC・ブラウザで開くと存在しないことがある。
  - 書き出し先は、プロジェクト相対（`exports/…`）なら移動しても残る。絶対パスは「あれば開く、無ければ書き出し直す」。
  - 元の動画は、送信前（`compute.mediaId` が無い）のプロジェクトでだけ必要。見つからなければ取り込み画面で［動画を選び直す］（`RelinkSource`）。解析済みの `source.sha256` があれば一致を確かめ、違う動画への差し替えを拒否する。送信済みなら不要（解析・描画・編集はサーバーの成果物とキャッシュで進む）。
- **フォルダ ⇄ zip**：zip は先頭に `<名前>.vvlog/` を持つ無圧縮 zip で、`cache/`（サーバーから取り直せる）・書きかけの `*.part`・空のフォルダを除く。取り込みは先頭フォルダの有無を問わず、`project.json` の位置で判断する。外へ出る項目があれば何も書かずに拒否する。往復でバイト列が一致することをテストで保証する。
- **互換を崩す変更が必要になったとき**：
  1. `schemaVersion` を 1 つ上げ、`domain/project.ts` の `migrate()` に旧版 → 新版の変換を足す（旧版の `project.json` は読めること。書き戻しは新版）。
  2. 旧版のアプリが新版のファイルを開いたときは `PROJECT_TOO_NEW`（「新しい版のアプリで作られています」）で開かない。ファイルは触らない。
  3. 変更前の版のフィクスチャを `fixtures/` に残し、`compat.test.ts` で「旧版 → 新版」を通す。
  4. 項目の追加だけ（既定値で補える）ならバージョンは上げず、`normalizeV1()` で補う。
