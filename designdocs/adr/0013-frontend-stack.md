# ADR-0013 フロントエンドのライブラリ構成

- 状態：採択
- 日付：2026-10-24

## 文脈
- Adobe 系の画面（ドッキングできるパネル、タイムライン、ビューア、インスペクタ、ダークテーマ）を 2 日で作る。
- 3 レーンが同じアプリに並列で手を入れる。状態管理と部品の作法を揃えないと衝突する。

## 決定
| 用途 | 採用 | 理由 |
|---|---|---|
| ビルド | Vite + TypeScript（strict） | Tauri 2 の標準テンプレート |
| UI 部品 | Radix UI Primitives + Tailwind CSS（デザイントークンは CSS 変数） | アクセシブルな素の部品。見た目はトークンで統一できる |
| パネル配置 | `react-resizable-panels` | ドッキング風の分割を最小コストで。自由なドッキング（ドラッグで移動）は P2 |
| アプリ状態 | Zustand（ストアは feature ごと） | ストアを feature 単位に分けられ、レーン間の衝突が少ない |
| サーバー状態 | TanStack Query | ジョブ・成果物の取得とキャッシュ、再取得 |
| API 型 | `openapi-typescript`＋`openapi-fetch` | 契約から型を生成。手書きの型ずれを防ぐ |
| 合成・描画 | WebGL2 を直接（小さなヘルパー `twgl.js`） | シェーダー 1 本の合成なので重いライブラリは要らない |
| タイムライン | 自作（Canvas 2D） | 要件が「再生ヘッド・区間・ユニットの帯・マーカー」だけで、既存ライブラリは動画編集向けに重い |
| アイコン | `lucide-react` | |
| テスト | Vitest（domain / application）、Playwright は使わない（2 日間では手動確認） | |
| 文言 | `src/presentation/i18n/ja.ts` に集約 | 将来の英語化 |

## 影響
- ストア・ユースケース・ポートの置き場所は [architecture/overview](../architecture/overview.md#4-デスクトップアプリの層とディレクトリ) に従う。
- 新しいライブラリの追加は、レーン内で閉じるなら自由、全体に効くもの（状態管理・UI 基盤）は ADR を足す。
