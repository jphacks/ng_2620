# フルモードと制限モードの機能差分表

[ADR-0015](../adr/0015-web-first-windows-local-server.md) で、Tauri を廃止してローカル Web サーバー＋ブラウザ UI にした。これに伴い、アプリには 2 つの動作モードがある。後続の実装チケット（#22〜#29、#37、#38）はこの表を基準にする。

| モード | 条件 | 画面の配信元 |
|---|---|---|
| **フル** | ローカルサーバー（`127.0.0.1`）が起動していて、SPA がそこから配信されている、または Pages 版から昇格できた（#38） | ローカルサーバー |
| **制限** | ローカルサーバーが無い。GitHub Pages の SPA だけで動いている | GitHub Pages |

モードは起動時に `platform.ts` が判定する（設計は #21）。画面と UI コードは両モードで同一ビルドを使い、違いはアダプタ（`FileSystem`・`Hasher`・`MediaProbe`・`LayerCache` など）の差し替えで吸収する。

## 共通の前提
- **対応ブラウザ**：Chrome／Edge と Safari（Mac）を保証する。Firefox は動けば可で、保証しない（#28）。File System Access API は Safari 非対応のため使わない。
- 画面は既定ブラウザの通常タブで動く（PWA 化は見送り）。
- **Safari の IndexedDB**：ITP により、一定期間操作がないとデータが消えることがある。制限モードでは重要なデータの zip 保存を促す（#27）。Pages から `127.0.0.1` への昇格（#38）は Safari では動かない前提で、案内リンクのみとする。
- 推論先（フル：ローカル GPU / 制限：外部 GPU）は `ComputeBackendPort` の接続プロファイルで切り替える（F03）。外部 GPU は BYO（利用者が用意）で、運営のホストは無い（#35）。
- 制限モードでも、外部 GPU サーバーにつながれば解析・描画・書き出しは行える。制限されるのは**ローカル資源へのアクセス**である。

## 機能ごとの差分
凡例：○ そのまま使える / △ 代替手段で使える（制約あり） / × 使えない

| 機能 | フル | 制限 | 制限モードでの代替・制約 |
|---|---|---|---|
| **F01 プロジェクト** 新規作成 | ○ 既定フォルダに `*.vvlog/` を作る | △ | メモリ上に作り、IndexedDB に保持する |
| F01 自動保存 | ○ 変更 1 秒後、一時ファイル→rename（原子的） | △ | IndexedDB へ自動保存。ブラウザのデータ消去で失われるため、zip 書き出しを促す |
| F01 開く・最近のプロジェクト | ○ フォルダ選択・最近の一覧（最大 20 件） | △ | zip のアップロードで開く。一覧は IndexedDB の保存分だけ |
| F01 保存先の指定・別名保存 | ○ サーバー側のネイティブダイアログ（#46） | △ | zip をダウンロードする（保存先はブラウザ任せ） |
| F01 削除（ゴミ箱） | ○ | △ | IndexedDB から削除。サーバー側データの削除（`DELETE /v1/projects/{id}`）は両モードで可 |
| **F02 動画の取り込み** ドロップ・ファイル選択 | ○ 選択はサーバー側のネイティブダイアログ（#46）、ドロップはサーバーの作業フォルダへストリーム取り込み（#47） | △ | `<input type="file">` とドロップ。`File` を仮想パスで登録し、メモリ／IndexedDB／GPU 直送で扱う |
| F02 メタ情報（probe） | ○ サーバー側の ffprobe | △ | `<video>` の `loadedmetadata`（長さ・解像度）。コーデックと音声の有無はサーバーの `ingest` に任せる |
| F02 sha256 | ○ サーバー側でストリーム計算 | △ | Web Crypto で計算。巨大ファイルはチャンクごとに逐次更新できないため、上限を設けて超えたら省略する（詳細は #27） |
| F02 アップロード（分割・再開） | ○ ローカル→外部 GPU も可 | ○ | ブラウザから分割アップロード（#25）。タブを閉じると再開できない |
| **F03 接続** ローカル GPU プロファイル | ○ | × | ローカルサーバーが無いので選べない（無効＋理由表示） |
| F03 外部 GPU プロファイル（URL＋トークン） | ○ | ○ | 外部サーバーは HTTPS・CORS・トークン必須（#36） |
| F03 トークンの保存 | ○ 設定ファイル（権限 600） | △ | `localStorage`／IndexedDB。共有 PC では保存しない選択肢を出す |
| **F04 解析ジョブ** | ○ ローカル GPU | △ | 外部 GPU のみ |
| **F05 進捗・キュー** SSE・再購読 | ○ | ○ | `fetch` のストリームで同一実装 |
| F05 通知 | △ Web Notifications（許可時のみ）。未許可は画面内トースト＋タブタイトル／ファビコンのバッジ（#48） | △ | 同左。タブが閉じていると届かない |
| F05 レイヤーキャッシュ | ○ ディスク（プロジェクトの `cache/`） | △ | IndexedDB／メモリ。容量上限があり、プロキシ解像度のレイヤーだけを保持する |
| **F06 キャスト選択** | ○ | ○ | 差なし |
| **F07 アバターライブラリ** | ○ フォルダに VRM をコピー、`library.json` | △ | アップロードした VRM を IndexedDB に保存。ブラウザのデータ消去で失われる |
| F07 重複判定（sha256） | ○ | △ | Web Crypto で計算（F02 と同じ制約） |
| **F08 描画ジョブ** | ○ ローカル GPU | △ | 外部 GPU のみ |
| **F09 エディタ** プレビュー合成（WebGL） | ○ | ○ | 同一実装 |
| F09 フレーム供給 | ○ ローカルサーバーの範囲読み（Range） | △ | IndexedDB／メモリのキャッシュ。先読みの量は小さくする |
| **F10 前後関係の手修正** | ○ | ○ | オーバーライドはプロジェクトに保存（保存先は F01 に従う） |
| **F11 書き出し** 合成・エンコード | ○ ローカル GPU | △ | 外部 GPU のみ |
| F11 保存先の選択 | ○ サーバー側のネイティブダイアログ（#46） | △ | ブラウザのダウンロード。保存先は指定できない |
| F11 「エクスプローラーで表示」 | × 今回は見送り（#28）。要望があれば後で追加 | × | ボタンを出さない |
| **F12 デモモード** サンプル | ○ | ○ | サンプルは Pages に静的ファイルとして同梱する |
| **F13 サーバー基盤** | ○ ローカルサーバーとして起動 | × | 制限モードでは自分では起動できない。外部 GPU 側の導入は #43 |
| **F14 モックサーバー** | ○ 開発用（macOS 含む） | ○ | 開発時のみ。接続先としては通常の外部サーバーと同じ |
| **F15 アプリ枠** 設定・テーマ | ○ 設定はサーバー側ファイル | △ | 設定は `localStorage`／IndexedDB。端末間で共有されない |
| F15 ネイティブメニュー・ショートカット | △ ブラウザのショートカットと衝突しないキーに再割当（#39） | △ | 同左 |

## 制限モードで使えない操作の UI 方針
- 使えない操作は**非表示にせず、無効化して理由を示す**。理由は 1 行（「ローカルアプリが必要です」）と、導入案内へのリンクを出す。
  - 例外：ブラウザでは意味をなさない操作（「エクスプローラーで表示」）は表示しない。
- 無効化の理由は 3 種類の文言に統一する。
  | 理由 | 文言の方針 |
  |---|---|
  | ローカルサーバーが必要 | 「ローカルアプリが必要です」＋導入ページへのリンク |
  | ブラウザの制約 | 「ブラウザでは保存先を指定できません」のように、代替手段（zip・ダウンロード）を併記 |
  | ローカル接続のみ | ネイティブダイアログはサーバー端末の画面に出るため、リモート接続・Pages 経由では無効（「この PC のローカルアプリに接続しているときだけ使えます」） |
  | GPU が未設定 | 「GPU サーバーに接続してください」＋接続設定を開くボタン |
- 制限モードの間は画面上部に常時バナー（「制限モード：データはこのブラウザに保存されます。定期的に zip で書き出してください」）を出す。閉じても、保存のたびにステータスバーで状態を示す。
- ローカルサーバーが後から見つかったときは、バナーに「フルモードに切り替える」を出す（#38）。
- 無効化の判定は `platform.ts` の機能フラグ（`capabilities.localFs`・`capabilities.localGpu` など）から行い、各画面が `mode` を直接見ない。
