## 1. 背景と課題

実写の vlog・撮影素材に映る人物を、**本人の動きのまま** VRM アバターへ置き換えたい需要がある（顔出しせずに投稿したい配信者、
撮影素材の人物を差し替えたい映像制作者）。既存の手段は次のどちらかで、どちらも重い。

- モーションキャプチャ機材＋3D 合成：機材と専門技能が要る。
- 手作業のロトスコープ・合成（After Effects 等）：1 秒あたり数十分〜数時間。特に**人物の手前にある物（机・楽器・通行人）との前後関係**が難所。

このリポジトリの推論パイプラインは、動画 1 本から「人物の追跡 → 3D メッシュ → 遮蔽判定 → 人物除去 → VRM 描画 → 合成」までを自動化している
（デモ用の RTX 5060 Ti で 10 秒・300 フレームが約 4 分）。足りないのは、**専門家でなくても使え、プロが結果を直せる**製品としての体験。

## 2. 目的（このハッカソンで示すこと）

1. **動画を入れてアバターを選ぶだけで、前後関係まで正しい置換動画が出る**体験を、Mac のデスクトップアプリで通しで見せる。
2. 自動結果が間違った箇所（物体が人物の前か後ろか）を、**再推論なしにその場で直せる**ことを見せる（プロ向けの価値）。
3. 将来の製品形（Mac＋専用 GPU サーバー、Windows ローカル GPU、エンタープライズ機能）へ伸ばせる構造であることを、設計で示す。

### 成功指標（デモ時点）

| 指標 | 目標 |
|---|---|
| 取り込みから最初のプレビュー（追跡マスク）まで | 10 秒・1080p の動画で **2 分以内**（L4 / RTX 級） |
| 取り込みから置換プレビューまで | 同 **8 分以内**（待ち時間中も段階的に結果が見える） |
| 前後関係の修正からプレビュー反映まで | **0.5 秒以内**（サーバー往復なし） |
| デモの完走 | 通信・GPU 障害時も、同梱の処理済みプロジェクトで編集〜書き出し済み動画の再生まで見せられる |

## 3. 想定ユーザー

| ペルソナ | 求めるもの | このアプリでの使い方 |
|---|---|---|
| **P1 VTuber・配信者** | 顔出しせずに実写 vlog を投稿したい。手間をかけたくない | ウィザードで取り込み → 自分を選び VRM を割り当て → 書き出し |
| **P2 映像制作者（プロ）** | 撮影素材の人物を差し替える。品質と制御が要る。既存の編集ソフトと並べて使う | 自動結果をエディタで確認し、前後関係の誤りを直してから書き出し |
| （将来）企業 | 映り込んだ人物の匿名化、チーム運用、監査 | スコープ外（[ADR-0010](adr/0010-out-of-scope-enterprise-and-later.md)） |

## 4. ユーザー体験の全体像

```
[ホーム] ─新規─▶ [取り込み] ─▶ [解析中（段階的プレビュー）] ─▶ [キャスト: 人物を選び VRM を割当] ─▶ [描画中] ─▶ [エディタ] ─▶ [書き出し]
   │                                  ▲ 待ち時間中に VRM を選べる                                    │ 前後関係を直す
   └─サンプルを開く / 最近のプロジェクト ─────────────────────────────────────────────────────────▶ [エディタ]
```

- **初回はウィザード型**（1 本道で迷わない）、**結果はエディタ型**（Adobe 系のパネル・タイムライン・インスペクタ）で直す（[ADR-0004](adr/0004-job-stages-and-progressive-results.md), [ux/README](ux/README.md)）。
- 処理は**ジョブキュー**で背後に回り、各段階の結果（追跡マスク → メッシュ → アバター）を**届いた順にプレビュー**する。

## 6. 非機能要件

| 区分 | 要件 |
|---|---|
| 対応 OS | **macOS 14+（Apple Silicon）= デモ・P0**。Windows 11 + NVIDIA GPU（ローカル推論）は P0 で接続経路のみ（ローカルサーバー起動の自動化は P1）。 |
| 性能 | エディタの再生は**プロキシ解像度（1080p の素材なら 540x960）で 30fps**。手修正の反映 0.5 秒以内。1 ジョブの GPU 処理は、L4 / RTX 5060 Ti で 300 フレームあたり 6 分以内。 |
| 信頼性 | ジョブ状態はサーバーに保存し、アプリを閉じても処理は続く。再接続時に状態を復元する。アップロード・ダウンロードは再開できる。 |
| データ | 動画はユーザーが選んだサーバーにしか送らない。サーバー側のデータはプロジェクト単位で削除できる（P0 は API のみ）。 |
| セキュリティ | サーバーは Bearer トークン必須（P0 は固定トークン）。リモート接続は HTTPS（トンネル経由）を前提とする。トークンは OS のキーチェーンに保存する（P1、P0 は設定ファイル）。 |
| ライセンス | 上流モデルのコードは各 LICENSE を同梱する。重みはリポジトリに置かず取得元から取得する。VRM ファイルはコミットしない（サンプルは描画済みレイヤーのみ）。VRM のメタ情報（利用許諾）を表示する。[ADR-0008](adr/0008-implementation-repo-and-model-placement.md) |
| 拡張性 | 推論の実行先（ローカル / リモート / 将来のクラウド）は `ComputeBackend` ポートで差し替える。書き出し形式は `Exporter` 種別で追加できる。 |
| UI 言語 | 日本語（文言は 1 か所に集約し、将来の英語化に備える）。 |
| 観測性 | サーバーはジョブごとに段階別の所要時間とログを保存し、アプリから閲覧できる（P1）。 |

## 7. 制約と前提

- **処理時間**：現行パイプライン（`--hmr_stride 3`）は RTX 5060 Ti で約 0.72 秒/フレーム（10 秒動画で約 4 分、プロキシ 540x960 では 1〜2 割増）。30 秒動画は約 11〜13 分かかるので、**デモは 10 秒前後の動画**で行い、
  長い処理はキューと段階的プレビューで体験を保つ。
- **人物数**：現行は最初のフレームで大きい順に `max_targets` 人（既定 2）を追跡する。P0 は上限 4 人、途中から入る人物は P2。
- **入力の処理解像度**：推論は内部で縮小した解像度（長辺 854px 程度）で行い、書き出しは元解像度（`--hq`）で合成する。
- **Mac で推論しない**：SAM3 / SAM-3D-Body は CUDA 前提。Mac は必ずリモート GPU に接続する（[ADR-0002](adr/0002-gpu-server-and-compute-backend-port.md)）。
- **実装は別リポジトリ**：ハッカソン指定のリポジトリに、アプリ・サーバー・パイプライン・モデルを置く（[ADR-0008](adr/0008-implementation-repo-and-model-placement.md)）。

## 8. スコープ外（今回の 2 日間では実装しない。設計上の拡張点だけ残す）

[ADR-0010](adr/0010-out-of-scope-enterprise-and-later.md) に理由と拡張点をまとめる。

- エンタープライズ機能：ユーザー認証・SSO、チーム・権限、ライセンス（席）管理、監査ログ、オンプレ配備の運用。**本実装は今回のスコープ外**。
- 書き出し形式の拡充（ProRes / PNG 連番 / レイヤー別 / モーションデータ）、Premiere・After Effects 連携。
- 人物の消去・ぼかし、途中から入る人物の追跡、30 秒超の動画、VRoid Hub 連携。
- Mac 上でのローカル推論、自動アップデート、コード署名・公証（デモは開発ビルド）。

## 9. リスク

| リスク | 影響 | 対策 |
|---|---|---|
| デモ会場の通信・GPU サーバー障害 | ライブ処理が見せられない | 処理済みプロジェクト同梱（F12）、事前に書き出した動画、ローカル Wi-Fi テザリング |
| 処理時間がデモ枠に収まらない | 待ちが長い | 10 秒動画、段階的プレビュー、ジョブを事前投入しておき「完了済み」を開く台本（[demo-script](ux/demo-script.md)） |
| 遮蔽物ユニットがフレーム間で途切れる（現行は数〜10 フレームで切れる） | クリック 1 回で区間全体を直せない | サーバーでユニットを区間方向に連結する（F10 / [pipeline-integration](architecture/pipeline-integration.md)）。不足分はブラシ（P1） |
| ゲート付きモデル（SAM3 / SAM-3D-Body）の取得に各自の許諾が要る | サーバーを立てられない | 早めに許諾を取る。手間ならチームの非公開 HF リポジトリにミラー（[ADR-0008](adr/0008-implementation-repo-and-model-placement.md)） |
| 3 レーンの契約ずれ | 結合時に動かない | 契約先行（Day 1 午前に固定）、モックサーバー、型生成、契約テスト（[parallel-plan](architecture/parallel-plan.md)） |
